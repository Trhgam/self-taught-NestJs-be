### Đường dẫn route trong 1 controller

Trong NestJS, bạn có thể định nghĩa đường dẫn route cho các phương thức trong controller bằng cách sử dụng các decorator như `@Get()`, `@Post()`, `@Put()`, `@Delete()`, v.v.

Nhưng 1 controller có thể có nhiều phương thức và mỗi phương thức có thể có một đường dẫn route khác nhau. Để tổ chức mã nguồn tốt hơn, bạn có thể sử dụng các module con (sub-modules) để nhóm các controller liên quan lại với nhau. Ví dụ, bạn có thể tạo một module con cho sản phẩm (ProductModule) và đặt tất cả các controller liên quan đến sản phẩm trong module này. Điều này giúp mã nguồn của bạn trở nên rõ ràng hơn và dễ dàng quản lý hơn khi ứng dụng của bạn phát triển.

Hay bạn có thể sử dụng các route prefix để định nghĩa một phần chung cho tất cả các phương thức trong controller. Ví dụ, nếu bạn có một controller quản lý sản phẩm, bạn có thể đặt route prefix là `/products` và sau đó định nghĩa các phương thức như `@Get()`, `@Post()`, v.v. sẽ tự động được gắn với đường dẫn `/products`. Điều này giúp giảm sự lặp lại và làm cho mã nguồn của bạn trở nên sạch sẽ hơn.

Ngoài ra trong 1 controller không thể dùng 2 methor cùng là method get nhưng /:id cùng nhau được
Tuy nó khong bị lỗi nhưng nó sẽ gây ra sự nhầm lẫn và khó khăn trong việc quản lý các route. Khi có hai phương thức cùng sử dụng method GET và có đường dẫn giống nhau (ví dụ: `@Get(':id')`), NestJS sẽ ưuu tiên gọi phương thức đầu tiên được định nghĩa trong controller, điều này có thể dẫn đến việc không mong muốn khi bạn muốn gọi phương thức thứ hai.

Ví dụ về sự xung đột

```ts
@Controller("products")
export class ProductController {
  // PHƯƠNG THỨC A
  @Get(":id")
  detailProduct(@Param("id") id: string) {
    return "Trả về chi tiết sản phẩm";
  }

  // PHƯƠNG THỨC B (Sẽ bị "tàng hình")
  @Get(":id")
  checkStock(@Param("id") id: string) {
    return "Kiểm tra kho hàng";
  }
}
```

Kết quả: Khi bạn gọi GET /products/123, máy chủ luôn chạy Phương thức A. Phương thức B vĩnh viễn không thể truy cập được.

### Cách giải quyết đúng đắn

Để có 2 phương thức GET cho cùng một đối tượng, bạn phải làm cho đường dẫn của chúng khác biệt hoàn toàn hoặc sử dụng Query Parameters.

#### Thêm tiền tố (Prefix)

```ts
@Controller("products")
export class ProductController {
  // PHƯƠNG THỨC A
  @Get(":id")
  detailProduct(@Param("id") id: string) {
    return "Trả về chi tiết sản phẩm";
  }

  // PHƯƠNG THỨC B
  @Get(":id/stock")
  checkStock(@Param("id") id: string) {
    return "Kiểm tra kho hàng";
  }
}
```

#### Sử dụng Query Parameters

```ts
@Controller("products")
export class ProductController {
  // PHƯƠNG THỨC A
  @Get(":id")
  detailProduct(@Param("id") id: string, @Query("action") action: string) {
    if (action === "stock") {
      return "Kiểm tra kho hàng";
    }
    return "Trả về chi tiết sản phẩm";
  }
}
```

#### Gộp chung Logic

```ts
@Controller("products")
export class ProductController {
  @Get(":id")
  handleProduct(@Param("id") id: string, @Query("action") action: string) {
    if (action === "stock") {
      return "Kiểm tra kho hàng";
    }
    return "Trả về chi tiết sản phẩm";
  }
}
```

### Một lỗi phổ biến khác (Thứ tự khai báo)

Hãy cẩn thận với thứ tự nếu một cái là chuỗi tĩnh (static) và một cái là tham số (dynamic):

Sai: Nếu đặt @Get(':id') trước @Get('search'). Khi bạn gọi /products/search, Nest sẽ hiểu search là một cái id và nhảy vào hàm chi tiết.

Đúng: Luôn đặt các Route tĩnh (như /search, /active) LÊN TRÊN các Route động (như /:id).

## Lưu ý: Không Đặt động trước tĩnh, đặt tĩnh trước động

Cách làm đúng

```ts
@Get('search') // (1) Kiểm tra xem có phải là chữ "search" chính xác không?
search() {
  return 'Đây là kết quả tìm kiếm';
}

@Get(':id') // (2) Nếu không phải "search", thì mới coi nó là một cái "id"
getDetail(@Param('id') id: string) {
  return 'Đây là chi tiết sản phẩm';
}
```

Trường hợp sai

```ts
@Get(':id') // (1) NestJS quét dòng này trước
getDetail(@Param('id') id: string) {
  return 'Đây là chi tiết sản phẩm';
}

@Get('search') // (2) Dòng này sẽ bị bỏ qua khi gọi /products/search
search() {
  return 'Đây là kết quả tìm kiếm';
}
```
