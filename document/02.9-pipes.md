## Pipes In NestJS

### What is a Pipe?

Pipes là một trong những thành phần quan trọng của NestJS, được sử dụng để xử lý dữ liệu đầu vào trước khi nó được truyền đến các handler của controller. Pipes có thể được sử dụng để thực hiện các nhiệm vụ như validation, transformation, hoặc bất kỳ logic nào khác liên quan đến dữ liệu đầu vào.

### Built-in Pipes

NestJS cung cấp một số built-in pipes phổ biến như:

- `ValidationPipe`: Dùng để tự động validate dữ liệu đầu vào dựa trên các decorators của class-validator.
- `ParseIntPipe`: Dùng để chuyển đổi dữ liệu đầu vào thành số nguyên.
- `ParseBoolPipe`: Dùng để chuyển đổi dữ liệu đầu vào thành giá trị boolean.
- `ParseArrayPipe`: Dùng để chuyển đổi dữ liệu đầu vào thành mảng.
- `ParseUUIDPipe`: Dùng để chuyển đổi dữ liệu đầu vào thành UUID.
- `ParseDatePipe`: Dùng để chuyển đổi dữ liệu đầu vào thành đối tượng Date
- `DefaultValuePipe`: Dùng để cung cấp giá trị mặc định nếu dữ liệu đầu vào không tồn tại.

### Custom Pipes

Ngoài các built-in pipes, bạn cũng có thể tạo custom pipes để thực hiện các logic xử lý dữ liệu đầu vào theo nhu cầu của bạn. Để tạo một custom pipe, bạn cần implement interface `PipeTransform` và override phương thức `transform`.

````typescript
import { PipeTransform, Injectable } from '@nestjs/common';

@Injectable()
export class MyCustomPipe implements PipeTransform {
  transform(value: any) {
    // Logic xử lý dữ liệu ở đây
    return value;
  }
}
``` Sau đó, bạn có thể sử dụng custom pipe này trong controller của mình bằng cách thêm nó vào decorator `@Body()`, `@Param()`, hoặc bất kỳ decorator nào khác mà bạn muốn áp dụng pipe cho dữ liệu đầu vào.
```typescript
@Post()
createProduct(@Body(new MyCustomPipe()) productDto: ProductDto): ResponseData<ProductDto> {
  // Logic xử lý tạo sản phẩm ở đây
}
````

### Tổng kết

Pipes là một phần quan trọng của NestJS, giúp bạn xử lý dữ liệu đầu vào một cách hiệu quả và dễ dàng. Bạn có thể sử dụng các built-in pipes để thực hiện các nhiệm vụ phổ biến hoặc tạo custom pipes để đáp ứng các yêu cầu đặc biệt của ứng dụng của bạn. Việc sử dụng pipes giúp mã nguồn của bạn trở nên sạch sẽ, dễ bảo trì và dễ hiểu hơn.

### Cách dùng

Có 2 cách dùng là dùng trong @Body, @Param, @Query, ... hoặc dùng trong toàn bộ controller bằng cách thêm vào decorator @UsePipes() ở trên class controller hay thêm vào hàm
@Post()
@UsePipes(ValidationPipe) trong file main.ts.

```typescript
import { Controller, Post, Body, ValidationPipe } from "@nestjs/common";
import { ProductDto } from "./product.dto";

@Controller("products")
export class ProductsController {
  @Post()
  @UsePipes(ValidationPipe)
  createProduct(@Body() productDto: ProductDto) {
    // Logic xử lý tạo sản phẩm ở đây
  }
}
```

---

Và tùy vào cách import nếu import ValidationPipe từ '@nestjs/common' thì sẽ phải thêm new ValidationPipe() còn nếu import từ file validation.pipe.ts thì sẽ không cần thêm new nữa.

Một vấn đè nữia là nếu ở file main.ts đã dùng app.useGlobalPipes(new ValidationPipe()) thì ở controller sẽ không cần dùng @UsePipes(ValidationPipe) nữa vì đã được áp dụng toàn cục rồi.

dễ import lộn ValidationPipe từ '@nestjs/common' và ValidationPipe từ file validation.pipe.ts nên cần chú ý khi import để tránh bị lỗi. Nếu import sai sẽ bị lỗi như sau:

```bash
Error: Nest can't resolve dependencies of the ValidationPipe (?). Please make sure that the argument at
index [0] is available in the current context.
```

1. Cách tạo Pipe tái sử dụng (Dynamic Regex Pipe)

```typescript
import { PipeTransform, Injectable, BadRequestException } from "@nestjs/common";

@Injectable()
export class DynamicRegexPipe implements PipeTransform {
  // Nhận regex và thông báo lỗi tùy chỉnh khi khởi tạo
  constructor(
    private readonly regex: RegExp,
    private readonly errorMessage?: string,
  ) {}

  transform(value: string) {
    if (!this.regex.test(value)) {
      throw new BadRequestException(
        this.errorMessage || `Dữ liệu "${value}" không đúng định dạng.`,
      );
    }
    return value;
  }
}
```

2. Tạo Object Constant để quản lý tập trung
   Bạn nên gom các Regex vào một file constants để dễ quản lý và bảo trì.

```typescript
// app.constants.ts
export const VALIDATION_RULES = {
  STUDENT_ID: {
    regex: /^SV\d{8}$/,
    message: "Mã sinh viên phải bắt đầu bằng SV và có 8 chữ số.",
  },
  EMPLOYEE_CODE: {
    regex: /^NV-[A-Z]{2}-\d{4}$/,
    message: "Mã nhân viên phải có định dạng NV-XX-0000.",
  },
};
```

3. Cách sử dụng trong Controller
   Khi sử dụng, bạn chỉ cần khởi tạo Pipe với quy tắc tương ứng từ Object Constant.

```typescript
@Controller("users")
export class UserController {
  @Get("student/:id")
  getStudent(
    @Param(
      "id",
      new DynamicRegexPipe(
        VALIDATION_RULES.STUDENT_ID.regex,
        VALIDATION_RULES.STUDENT_ID.message,
      ),
    )
    id: string,
  ) {
    return { studentId: id };
  }

  @Get("employee/:code")
  getEmployee(
    @Param(
      "code",
      new DynamicRegexPipe(
        VALIDATION_RULES.EMPLOYEE_CODE.regex,
        VALIDATION_RULES.EMPLOYEE_CODE.message,
      ),
    )
    code: string,
  ) {
    return { employeeCode: code };
  }
}
```

Tóm lại, trong NestJS, bạn có 3 cách chính để custom Pipe, tùy thuộc vào độ phức tạp và khả năng tái sử dụng mà bạn mong muốn.

Dưới đây là bảng so sánh để bạn chọn "vũ khí" phù hợp cho dự án Học Từ Thiện:

### 1. Cách dùng Class Kế Thừa (Cách ta vừa làm - Pro nhất)

Bạn tạo một lớp cha (DynamicRegexPipe) và các lớp con kế thừa (ParseMenteeIdPipe).

Đặc điểm: Tận dụng OOP, dùng tên lớp để validate.

Khi nào dùng: Khi bạn có các quy tắc định danh cố định xuyên suốt dự án (ID học viên, mã Mentor, mã khóa học).

Ưu điểm: Cực sạch, hỗ trợ Dependency Injection (check DB), đúng chuẩn NestJS.

```ts
// 1. Lớp cha (Core Logic)
export class DynamicRegexPipe implements PipeTransform {
  constructor(protected regex: RegExp, protected message: string) {}

  transform(value: string) {
    if (!this.regex.test(value)) throw new BadRequestException(this.message);
    return value;
  }
}

// 2. Lớp con (Specific Implementation)
export class ParseMenteeIdPipe extends DynamicRegexPipe {
  constructor() {
    super(/^ME\d{8}$/, 'Mã học viên không hợp lệ.');
  }
}

// Cách dùng trong Controller
@Get(':id')
findOne(@Param('id', ParseMenteeIdPipe) id: string) {}
```

### 2. Cách dùng Factory Function (Cách dùng hàm)

Dùng một hàm tiện ích (util) để khởi tạo nhanh Pipe.

Đặc điểm: ParseCustomId('KEY').

Khi nào dùng: Khi dự án nhỏ, lười tạo nhiều file class con, hoặc chỉ cần validate nhanh các chuỗi đơn giản.

Ưu điểm: Viết cực nhanh, không tốn file.

```ts
export const ParseCustomId = (regex: RegExp, message: string) => {
  return new DynamicRegexPipe(regex, message);
};

// Cách dùng trong Controller
@Get(':id')
findOne(
  @Param('id', ParseCustomId(/^MT-\d{4}$/, 'Mã Mentor sai')) id: string
) {}
```

### 3. Cách dùng Trực Tiếp (Inline/Manual)

Viết logic xác thực ngay trong hàm transform của một Pipe duy nhất cho một mục đích duy nhất.

Đặc điểm: Tự viết new DynamicRegexPipe(/.../, '...') ngay tại @Param.

Khi nào dùng: Khi cái Regex đó chỉ dùng đúng một lần duy nhất trong toàn bộ dự án và không bao giờ lặp lại.

Nhược điểm: Code rác, khó bảo trì, vi phạm nguyên tắc DRY (Don't Repeat Yourself).

```ts
@Get(':id')
findOne(
  @Param(
    'id',
    new DynamicRegexPipe(/^CRS-[A-Z]{3}$/, 'Mã khóa học phải có 3 chữ cái trở lên')
  )
  id: string
) {}

```
